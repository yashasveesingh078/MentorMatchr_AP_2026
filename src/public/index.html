How MentorMatchr Works

An end-to-end, database-driven pipeline that replaces ad-hoc spreadsheets with mathematical domain and keyword matching.

Step 01

Controlled Taxonomy

Faculty domains, areas of expertise, and technical keywords are stored in normalized master tables. This eliminates spelling anomalies, duplicate tags, and fragmented data.

Step 02

Problem Scoping

Each hackathon problem statement is tagged with exactly one primary domain and required keywords. BCNF decomposition guarantees the problem cannot belong to multiple events.

Step 03

Relational Scoring

A deterministic SQL matching engine weights primary/secondary domain affinity (60%) and keyword tag intersection (40%) into transparent, explainable compatibility percentages.

Step 04

Capacity & Auditing

Partial unique indexes enforce at most one active mentor per team, while application guards ensure no faculty exceeds their maximum team workload.

Explainable Scoring Formula
DETERMINISTIC ALGORITHM

Domain Affinity Weight: 60%

If the faculty member's Primary Domain matches the problem statement's domain, 60 points are awarded. If it matches a Secondary Domain, 45 points are awarded.

Technical Tag Overlap Weight: 40%

Calculates the intersection of technical keywords required by the problem and those possessed by the faculty member:
Keyword Points = (Matched Tags / Total Problem Tags) × 40
